# 4.3.1 VLAN-ok közötti forgalomirányítás egy 3. rétegbeli switch-en

## Miért válasszunk 3. rétegbeli switch-et?

A router-on-a-stick megoldás **kis- és közepes hálózatokban** megfelelő, de vállalati környezetben nem skálázható elég hatékonyan. A **3. rétegbeli switch** (multilayer switch) az ipari standard megoldás nagyvállalatoknál.

---

## Hogyan végez 3. rétegbeli switch VLAN-ok közötti forgalomirányítást?

Két fő mechanizmus:

### 1. SVI (Switched Virtual Interface) – VLAN-ok közötti forgalomirányítás

Minden irányítható VLAN-hoz létrehozunk egy SVI logikai interfészt. Az SVI az adott VLAN alapértelmezett átjárójaként működik.

```
D1(config)# interface vlan 10
D1(config-if)# ip address 192.168.10.1 255.255.255.0
D1(config-if)# no shutdown
```

### 2. Irányított port (Routed Port) – külső hálózathoz való csatlakozáshoz

Egy 2. rétegbeli port átalakítható 3. rétegbeli „irányított porttá" a `no switchport` paranccsal. Így csatlakozhat a switch egy routerhez vagy másik 3. rétegbeli switch-hez IP-alapon.

```
D1(config)# interface GigabitEthernet0/0/1
D1(config-if)# no switchport
D1(config-if)# ip address 10.10.10.2 255.255.255.0
```

---

## A 3. rétegbeli switch képességei

| Képesség | Leírás |
|---|---|
| SVI-alapú inter-VLAN routing | Több VLAN közötti forgalomirányítás virtuális interfészeken keresztül |
| Irányított port (routed port) | 2. rétegbeli port → 3. rétegbeli interfész (`no switchport`) |
| Hardveres kapcsolás | Sokkal gyorsabb, mint a szoftveres router-on-a-stick |
| `ip routing` parancs | Engedélyezi az IPv4-alapú forgalomirányítást a switch-en |

---

## ip routing – kötelező lépés!

```
D1(config)# ip routing
```

Ezt a parancsot **mindig ki kell adni** a 3. rétegbeli switch-en, különben az SVI-k nem fognak VLAN-ok között irányítani – csak felügyeleti célra használhatók.
