# 3.5.3 A DTP-konfiguráció eredményei

## Eredménytáblázat

Az alábbi táblázat megmutatja, hogy az S1 és S2 switch-ek portjainak különböző DTP-módjai kombinálva milyen eredményt hoznak – trönk jön-e létre vagy sem.

| S1 módja ↓ / S2 módja → | **dynamic auto** | **dynamic desirable** | **trunk** | **access** |
|---|---|---|---|---|
| **dynamic auto** | ❌ Access | ✅ Trunk | ✅ Trunk | ❌ Access |
| **dynamic desirable** | ✅ Trunk | ✅ Trunk | ✅ Trunk | ❌ Access |
| **trunk** | ✅ Trunk | ✅ Trunk | ✅ Trunk | ⚠️ Korlátozott |
| **access** | ❌ Access | ❌ Access | ⚠️ Korlátozott | ❌ Access |

> ⚠️ **Korlátozott:** Konfigurációs inkonzisztencia – a `trunk` oldal trönkként működik, de az `access` oldal nem; kommunikáció csak a natív VLAN-on lehetséges, hibajelzés keletkezhet.

---

## A legfontosabb kombinációk

### dynamic auto + dynamic auto → Access (inaktív trönk)

Mindkét oldal vár a másikra – **trönk nem jön létre**. Ez a leggyakoribb hiba, amikor mindkét switch alapértelmezett beállításon marad.

```
S1: switchport mode dynamic auto   ← vár
S2: switchport mode dynamic auto   ← vár
→ Eredmény: access kapcsolat (nincs trönk!)
```

### dynamic desirable + dynamic auto → Trunk

Az egyik oldal aktívan kezdeményezi a trönkot.

```
S1: switchport mode dynamic desirable  ← kezdeményez
S2: switchport mode dynamic auto       ← elfogadja
→ Eredmény: trönk ✅
```

### trunk + trunk → Trunk (ajánlott, statikus)

```
S1: switchport mode trunk
S1: switchport nonegotiate
S2: switchport mode trunk
S2: switchport nonegotiate
→ Eredmény: trönk, DTP nélkül ✅
```

---

## Best practice összefoglalás

| Szituáció | Ajánlott beállítás |
|---|---|
| Trönkkapcsolat switch-switch között | `trunk` + `nonegotiate` mindkét oldalon |
| Végfelhasználói port (PC, IP telefon) | `access` mindkét oldalon |
| Nem-Cisco eszköz csatlakoztatása | `trunk` + `nonegotiate` a Cisco oldalon |
| DTP kikapcsolása az összes nem-trönk porton | `switchport mode access` |

---

## Miért veszélyes a DTP?

A DTP **biztonsági kockázatot** jelent, mert egy rosszindulatú eszköz DTP-kereteket küldve **trönkot hozhat létre** egy felhasználói porttal, és így hozzáférhet az összes VLAN forgalmához (**VLAN hopping**). Ezt megelőzi a `switchport nonegotiate` parancs.
